### 核心审计结论
- 项目：PHP 8.2 + ThinkPHP 8，165 个 PHP 文件约 4 万行，17 张 MySQL 表，Nginx+PHP-FPM + crontab(certtask) + Supervisor 守护 Swoole 常驻(dmtask)。
- **致命约束**：Workers/Pages 不跑 PHP，无 ssh2/sockets/ftp/Swoole，无状态、有 CPU 时限。「PHP原样+Worker原生+D1+100%功能」不可兼得。
- 好消息：22 个 DNS 平台、14 个云 SDK、MCP(JSON-RPC over POST)、46/51 部署目标、webhook 通知、鉴权(自研无状态 authcode cookie) 全是纯 HTTP，可高保真迁移。
- 硬骨头：① 容灾 dmtask 是 Swoole while(true)+协程+ICMP/TCP（改 Cron 分钟轮询+HTTP探测）；② ACME 依赖 openssl+临时文件+sleep（改 WebCrypto）；③ SSH/FTP/local 部署 4 个目标无解；④ 默认 SMTP 需换 HTTP 邮件 API。
- SQL 兼容：仅需改约 10 处（SHOW TABLES、REPLACE INTO、NOW()、INTERVAL、OPTIMIZE TABLE、select version()、install.sql/update.sql DDL）。
- 备份：原系统无任何数据库备份导出功能，需从零建设（导出 SQLite dump + 导入恢复 + MySQL mysqldump 格式转换）。

### 关键坑（已解决，勿重犯）
1. wrangler [assets] 默认优先于 Worker，会消费 POST body → 必须 `run_worker_first=true`；fetch 里 assets 只对静态扩展名 GET 且用 request.clone()。
2. authcode 的 keyc 生成必须 `md5().slice(-4)` 不能用 substring(-4)（后者返回整串导致解密失败）。
3. QueryBuilder.join 表名自动加前缀，但 ON 条件里的表名要手写完整 `dnsmgr_account.id`。
4. 备份导入 splitSql 要先滤掉 `--`/`#` 注释行；convertMysqlStatement 里 REPLACE INTO 替换不能误伤 `INSERT OR REPLACE INTO`。

## 追加需求：Cloudflare 一键部署 + GitHub Action + 详细教程

用户要求：能通过连接 GitHub 账号一键部署、或 GitHub Action 部署，README 写详细教程。

### 调研到的官方机制（2026 最新）
- 一键部署按钮：`https://deploy.workers.cloudflare.com/?url=<repo>[/tree/main/<子目录>]`，Cloudflare 自动 clone 仓库到用户账号、自动创建并绑定 D1/KV/R2 等资源、自动改写 wrangler 配置里的 ID、用 Workers Builds 部署。仅支持 public 仓库 + Workers（不支持 Pages/私有仓）。
- **子目录必须完全自包含**（Cloudflare 把子目录当作新仓库根），否则构建失败。
- D1 migration：在 package.json 的 deploy 脚本里写 `wrangler d1 migrations apply DB --remote && wrangler deploy`，用 binding 名 DB。package.json 可加 `cloudflare.bindings.<name>.description` 给一键部署页展示说明。
- GitHub Action：`cloudflare/wrangler-action@v4`，参数名 `apiToken`/`accountId`/`workingDirectory`/`command`（驼峰），secrets 用 CLOUDFLARE_API_TOKEN + CLOUDFLARE_ACCOUNT_ID。
